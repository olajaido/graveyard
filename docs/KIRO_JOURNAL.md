### 3 Nov — Steering review *(manual)*
- **What I corrected (8 model defects found before any code):**
  1. S1 deprecation rule would have marked healthy packages Dead (resolved vs latest version).
  2. Division by zero when no signals are present, so an Unknown state was added.
  3. Fresh CVEs on healthy packages would be marked Cursed.
  4. Resting threshold was undefined.
  5. r6 was ambiguous.
  6. Scorecard −1 was not treated as missing.
  7. Exposure formula was ambiguous.
  8. Invariants were too vague for Hypothesis.
- **Also corrected (IAM):** split into Reader and Rites GitHub Apps so scanning code can never open PRs.
- **PRD:** v1.2.

### 3 Nov — Workspace gotcha *(manual)*
- **Surprise:** steering and hooks didn't load at all. The repo was nested inside a parent folder that was open as the workspace root, and Kiro only reads `.kiro/` at the workspace root.
- **Fix:** removed the empty outer `.kiro` and opened the repo folder directly.
- **Lesson:** always open the repo root itself as the workspace.

### 3 Nov — Data-source spikes
- **Spec/task:** none, Default mode. Throwaway PEP 723 scripts in `spikes/` → `docs/SPIKES.md`.
- **Kiro features:** agent shell execution with approval (Autopilot off for installs).
- **Findings that changed the design (ADR 0001):**
  - Syft v1.56.0 gives a usable dependency graph, so no custom parsers are needed.
  - Syft provides no runtime/dev scope (new requirement EX-8).
  - PyPI exposes no death signal at all, and dead packages still claim "Production/Stable".
  - deps.dev v3 has no dependents count, so popularity uses downloads.
  - GitHub is the only source for archived status, push date, commit authors and issue counts, so the GitHub Reader app is P0.
- **Real-data validation:** under the original S1 rule, express, uuid and moment would have been falsely marked Dead.
- **Cost lesson:** about 20 credits, partly spent on Kiro running git (push, PR, merge). From now on I do git myself.

### 3 Nov — Spec `mortality-model`: review and revision *(manual review + Kiro revision)*
- **What I corrected (12 defects before any code):**
  1. Invariant I1 was unbounded without input validation.
  2. Anchors were contradictory or untestable (six, moment, request).
  3. Resting could be granted when vulnerability data was missing.
  4. Cursed was undefined when an advisory date was unknown.
  5. Packages with no paths had no defined place in the sort.
  6. Config was unvalidated (e.g. `span = 0` causes division by zero).
  7. Tuning literals were not in YAML.
  8. `dead_reason` and `contributions` fields were missing.
  9. Months were pre-computed instead of passing dates.
  10. S1 precedence was unclear.
  11. Anchors needed to be driven by fixtures.
  12. Monotonicity was missing for r6.
- **Kiro got right:** applied all 12 in one pass (**10.88 credits**). The result is 52 requirements and 21 tasks, with design, tasks, steering and PRD §7 kept in sync.
- **Lesson:** reviewing the spec costs nothing; finding these bugs later in the code would have cost credits and trust.

### 3 Nov — Design and tasks review *(manual, pending application)*
Findings to apply before the first task runs:
1. No project scaffolding task yet: `pyproject.toml` (uv), pinned dependencies, pytest `property` marker, Hypothesis profiles (CI 500 / dev 200), ruff and mypy.

8. The anchor-capture script needs a read-only GitHub token from the environment.
9. Compare contribution sums with `math.isclose`.
