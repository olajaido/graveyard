# Implementation Plan: dependency-graph

## Overview

Implements `.kiro/specs/dependency-graph/requirements.md` per `.kiro/specs/dependency-graph/design.md`: CycloneDX ingest into a `package_key` graph, lockfile scope parsers, exposure inputs (`PathInfo` sets, `services_affected`), and example and witness paths, in `backend/core/graph/`. Each implementation task includes its own example tests and property tests as sub-tasks (DG-NFR-4). T0 is fixtures and scaffolding, so it carries fixture-integrity tests instead of properties.

## Task Dependency Graph

```mermaid
graph LR
  T0 --> T1 --> T2 --> T3 --> T4 --> T5 --> T6 --> T7 --> T8 --> T9 --> T10
```

T4–T6 depend only on T0, T1 and T3, and T7 needs all of them for the end-to-end checks. The chain is kept linear so each task starts from a green suite.
