# Implementation Plan: eval-harness

## Overview

Implements `.kiro/specs/eval-harness/requirements.md` per `.kiro/specs/eval-harness/design.md`: the labelled set and its merge command, the `coroner` custom agent, the manual capture script, the offline harness in `backend/eval/` (metrics, gate, without-GitHub view, `results.json`), and the confidence-band constants in `backend/core/bands.py`. Each implementation task carries its own tests as sub-tasks. The data-independent code is finished and green at T10. T11 to T14 are **MANUAL** tasks for the maintainer (permission probes, coroner labelling with the merge, the capture with a GitHub token, the label review). The tests that need the real data are written last, in T15, and the final gate is T16.

**Working rules for every task the agent runs:**
- Run every Python tool from `backend/` with `uv run` (`tech.md`). No `PYTHONPATH`.
- No task adds a dependency. `uv.lock` must not change.
- The only new file in `core/` is `backend/core/bands.py`. No task edits `core/scoring/`, `weights.v1.yaml`, `sources/` or `cli/`.
- The agent never runs `scripts/capture_eval.py` or `scripts/capture_anchors.py`, never runs the coroner, and uses no network. Nothing is committed by the agent; commits named in manual tasks are the maintainer's.
- Before each task, read the `EV-*` IDs it names in `requirements.md`; requirements win over the design if they differ.
- **Stop conditions are marked in bold. When one fires, stop and report instead of changing a literal or a threshold.**
- **When execution reaches a task marked MANUAL, stop and hand over to the maintainer. Do not carry out its steps.**

The chain is linear so every task starts from a green suite, and no real-data test exists before T15.
